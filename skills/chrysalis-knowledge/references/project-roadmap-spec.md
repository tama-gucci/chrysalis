# Project staging, integration and status
Ask for title/id, purpose, exit criteria, pillar intent, horizon and concrete deliverables. Dates stay
unknown when unsupported. Use `_types/project.md` and the project template; stage off-peak exploration
without automatically promoting it. Preserve all timeline deliverables in the ledger and ground source
and knowledge links. `project.reconcile` provides the additive diff; review changed and omitted items.
`horizon` drafts missing near-term/uncertain tasks and project task_ref updates; future work stays inert
in the ledger. Estimates use modality multipliers, and tasks inherit project knowledge links.
For integration, ask for the chosen pillar/track, then propose Life-Roadmap milestone/tag registration,
Memory active_horizons membership, project active status/pillar/last_updated and near-term tasks as
one reviewed set. Do not derive a personal pillar from a source or create a duplicate multiplier table.
`project.status` returns staged/active/paused/complete/archived projects and deliverable ratios.
Reconcile completed task evidence back into deliverables and strategic checklists with original
revisions; do not claim Dashboard/Calendar changed until readback. Projects contain Roadmap.md and
references, while original artifacts remain in the vault's shared Attachments/Originals boundary.
