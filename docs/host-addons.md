# External host tools

Use the [compatibility policy](compatibility.md) for tool grants, resource selection, provider/UI
packages and the host trust boundary. External packages remain independently installed. Native
/chrysalis tools review <name> creates an exact version 2 grant in private host-addons.json.
Unknown tools receive a scoped denial; registered unrelated tools remain available for review.
Do not run competing memory engines together. Version 1 read-only grants remain supported without
silent conversion; review their replacement before adding version 2 grants.

External research, recall and questionnaire results are passive evidence. Use bounded public
queries, primary citations and minimal disclosure. Lasting decisions and each new atomic note
retain their existing native proposal/approval boundaries. Model-tool grants do not authorize memory export into source or direct authoritative-vault writes.
Extensions remain trusted host code and can perform side effects outside these model-tool gates;
review their implementation and native scope before enabling them.
