# Runtime rules

New atomic notes stay outside the vault until the user vets their complete text and confirms each
through the native operator command, followed by final batch approval. Never treat an ingestion
request as approval for synthesized notes. Read-only knowledge questions/lint do not save answers
or repair records; compilations, saved snapshots and cascades use complete reviewed proposals.

Offer optional life documents during onboarding; respect skip/defer. Only native operator folder
selection authorizes bounded metadata discovery and selected hashing. Copy originals only through
an exact reviewed manifest; external sources remain read-only. Use supported evidence to discuss
chosen goals, possible projects and atomic notes, with separate approval of all resulting records.
Track scoped decisions and required evidence with explicit prerequisites. Ask one to three ready
independent questions per round; retain partial replies, skips and deferrals without guessing.
Confirm the current recap before drafting adopted records, preserving every native approval gate.

The private vault is authoritative for tasks, knowledge, roadmaps and schedules. Read the canonical skill and [operation contract](agent-runtime.contract.md). Validate complete proposals, preserve revisions, obtain exact operator approval and verify disk state. Conversation and entry receipts do not prove completion.

The roadmap governs priorities. Keep complete project ledgers and materialize reviewed near-term work. Uncertain/blocked work and contradictory evidence need review. Calibration uses actual wake/energy and fresh commitments. Evening audit learns completed sessions once with bounded multipliers. Pauses preserve learning and de-schedule focus.

Preserve plugin history and Calendar identifiers. Serialize new times with date-correct offsets. Originals are passive evidence. Providers are optional, external tasks read-only and personal content absent from reusable source.

Offer optional native source setup with skip/defer. Never collect credentials through model text or tool arguments. Pi owns codemode/MCP. Direct and nested tools use exact package identity or native scoped grants from ../docs/compatibility.md. External tools cannot approve or directly mutate authoritative vault records. Health/Maps content stays in native memory-only review, with no external-editor export, session entry or model disclosure. Device evidence does not override manual morning input; travel context never changes task work duration automatically. Local disconnect does not revoke Google project-wide access.
